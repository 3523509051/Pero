# 全群接入与微信组合启动检查

- Verdict：PASS（离线接入、实际服务启动及源码检查范围）。
- 基准：origin/main，4841a226048f756487b8c3f2b603bdf56d157140。
- 范围：新增组合启动入口与群扫描配置、会话接入开关、双方接入文档；不替换其它未选入文件。

## 需求与边界

组合启动扫描当前已登录微信的全部群，自动对齐 WS、账号、独立令牌、路由、允许会话和发送范围。新增群默认接入，已有 Agent 绑定、群关闭覆盖及主人访问范围保持。微信客户端不由脚本启动、登录或关闭。

## 实现核对

桥承担数据库扫描，Pero 仅在脚本边界调用独立桥进程；Core 不 import webot。先验证端口，再扫描、校验、备份并更新本机配置，写入失败回滚。扫描失败、空结果、账号变化和 ID 冲突不覆盖群配置。

令牌采用既有当前用户 DPAPI，经环境变量交给桥；JSON 只保存环境变量名。保存的群开关经版本化配置传到 Core，入站与投递均检查；Manager 确认配置应用后再启动桥。手动关闭不因再次扫描而自动复位。

## 验证

- 独立配置核对：全群路由、发送目标、数字映射、幂等重扫、其它账号及显式禁用保留、失败保护。
- 真实 Core／Manager／Windows 启动器连接模拟桥：共享认证、群名、API 保存群关闭、停止重启后新增群及群改名、关闭覆盖仍有效、正常退出。
- 旧普通启动器的真实隔离启动、重复启动、端口冲突、认证、停止及异常退出清理通过。
- 群关闭同时阻止后续投递；后台完成回报的既有定向用例通过。
- TypeScript 与 Vite 生产构建通过，Python 语法和发布文档链接核对通过。

## 提交与凭据

只从已发布 main 构造本轮明确文件差异，不合并原开发分支历史。运行配置、加密令牌、群扫描清单和备份不提交。推送前扫描实际 Git 树的已知本地凭据与常见密钥模式。

## 实测限制

没有打开微信、调用真实数据库或发送真实微信消息；微信扫描适配以桥现有数据库契约编写，仍需用户在已登录环境实机确认。运行中不持续热发现新群，重新组合启动时扫描。关闭群阻止 Core 正常处理与新投递，不意味着桥不读取该群数据库。
