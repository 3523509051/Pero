# Pero 接入契约

本文描述当前消息桥接入的最低要求、可选扩展和设备接入方向。实现依据为 `core/contracts.py`、`channels/onebot11/server.py`、`mapping.py` 及其资源查询实现。旧 `channel-contract.md` 含历史阶段说明，不能据此认定当前仍不支持私聊。

## 1. 职责

Pero 提供人格、对话参与策略、动态上下文、L1/L2/L3/L4/L10/L20、事件日记、独立知识库、工具和插件运行，以及控制室。消息桥或设备网关提供平台身份、消息接收、资源获取、输出执行及事实回执。

桥不需要实现另一套 Agent 或复制 Pero 的记忆系统。接入后可复用已有能力，但仍需配置 Agent 路由、会话授权、模型、工具权限及知识库；“复用”不等于不同平台自动共享身份与全部资料。

## 2. 两种接入方式

| 方式 | 当前性质 | 适用对象 |
| --- | --- | --- |
| OneBot v11 反向 WebSocket | 已有网络适配器；桥连接到 Pero 配置的监听地址与路径 | 实时通信桥、能转换事件和动作的设备网关 |
| 自定义 ChannelAdapter | 宿主内的开发契约；需要注册、装配并对接编排实际调用接口 | 使用 MQTT、自定义 WebSocket 等协议的开发者 |

内部协议定义 `receive() -> AsyncIterator[InboundMessage]`、`send(OutboundAction) -> SendReceipt`、`status()`。仅实现这三个方法不保证已经完成现有编排的所有装配；开发者还需对照当前通道绑定、生命周期、动作发送与查询调用实现。它不是现成的远程插件安装接口。

HTTP 会话接口可供网页/应用发起请求；它和自动接收桥事件、实际发送回执是不同入口，不能把一次 HTTP 返回直接当成设备已经播放或微信已经发送。

## 3. OneBot 最低契约

### 连接

- 桥连接到配置的 WebSocket 地址，路径默认为 `/ws`，端口按部署配置。
- 握手头 `X-Self-ID` 提供合法数字账号 ID，入站事件 `self_id` 与连接账号一致。
- 配置令牌时按适配器支持的方式认证，推荐 `Authorization: Bearer <token>`。令牌由部署配置提供，不写入公开示例或事件正文。
- 同账号重复连接当前拒绝新连接；网关应处理断线重连，不能依靠第二连接接管。

### 入站

以下为群聊结构示例，数字与时间仅用于说明：

```json
{
  "time": 1795305600,
  "self_id": 10001,
  "post_type": "message",
  "message_type": "group",
  "sub_type": "normal",
  "message_id": 12345,
  "group_id": 20001,
  "user_id": 30001,
  "message": [{"type": "text", "data": {"text": "你好"}}],
  "sender": {"user_id": 30001, "nickname": "示例用户"}
}
```

私聊使用 `message_type=private` 和对端 `user_id`；必须通过 Pero 现有私聊授权流程才能进入正式对话。群聊须配置账号/目标到 Agent 的路由及允许会话，唤醒和参与策略由 Pero 判断。

桥应声明消息 ID 的稳定范围：若 ID 只在单次桥进程内有效，就不能宣称支持跨重启严格去重。设备或平台已有稳定消息 ID 时应保留，并在映射中保持可追溯关系。

### 身份

稳定身份由通道、连接账号及发送者 ID 共同确定；会话还包含群聊/私聊类型及目标。昵称、群名和设备别名只能作为展示名称，不用于跨平台合并。

当前 OneBot 出站编码使用数字账号及目标 ID。MQTT topic、设备 UUID、MAC 地址等字符串不能直接充当当前编码器的目标；网关需持久维护稳定映射，重启后不能随意重新编号。

### 出站与回执

Pero 发送 `send_group_msg` 或 `send_private_msg`，带目标、消息内容及本次传输 `echo`。桥须返回对应 `echo`，不能以另一个请求的迟到回执完成当前请求。

普通成功回执示例：

```json
{
  "status": "ok",
  "retcode": 0,
  "data": {"message_id": 67890},
  "echo": "本次请求携带的原值"
}
```

仅在平台或设备确实达到约定的送达条件后返回成功；排队成功、点击发送、网络已写入或音频尚未播放不能随意等同于“用户已经收到”。失败/未知需按当前 `mapping.py` 的回执结构返回。无 echo、断连和超时通常只能判为 unknown，不自动重发。

`action_id` 为业务动作标识，`echo` 为本次传输关联标识，二者不要混用。发送和只读资源查询的状态分别处理，查到图片不代表已发送图片。

## 4. 可选增强契约

| 能力 | 当前方式 | 无该能力时 |
| --- | --- | --- |
| 图片输入 | 支持的消息段和受控资源字节 | 可以接收说明，但不能声称模型已获得原图 |
| 可信引用与文件事实 | `pero_ext` v1；按当前扩展白名单提供身份、引用、文件元数据 | 保留未知，不能猜测引用作者或把文件名当文件内容 |
| 文件获取 | `pero_file_bytes_v1`、`pero_file_chunk_v1` 与相应校验/查询信封 | 文件处理能力不可用，不能读取桥机器上的任意路径 |
| 引用原图 | `pero_quote_image_v1` | 按真实状态说明找不到引用图，不以另一张图替代 |
| 媒体发送 | 配置的版本化媒体动作，例如 `pero_media_send_v1`，按文字和图片分项返回回执 | 仅使用已适配的发送能力，不能把文本成功当图片也成功 |
| @ 与回复定位 | 稳定目标身份、消息段及桥的实际执行能力 | 文本提及与真实 @ 分开说明 |

这些扩展不是 OneBot v11 原生通用能力。第三方桥需逐项实现或新增适配；不能据协议名称宣称全部功能即插即用。字段和载荷校验以当前代码为准，公开版本应提供固定版本契约与兼容表。

## 5. ESP32 与虚拟伴侣

推荐将低功耗终端与 Agent 服务分开：

```text
ESP32：麦克风 / 按键 / 屏幕 / 扬声器 / 传感器
                     ↕ 设备协议
网关：身份与会话映射 / ASR / TTS / 消息转换 / 执行回执
                     ↕ OneBot v11 或新增适配器
Pero：人格 + 动态上下文 + 记忆 + 知识库 + 工具与插件
```

典型流程：设备触发输入，网关转为文本和可信设备/用户标识，Pero 运行会话与工具，网关把回复显示或合成为语音，设备/网关按明确约定返回结果。具体送达条件需区分设备接收、文本呈现和音频播放，当前 SendReceipt 不自动提供完整语音播放状态机。

传感器值可以由网关转为带来源的事件，或通过另行实现的工具读取；灯光、表情动画、舵机等动作需要独立定义工具、执行端和回执。不要把传感器状态伪造成用户说过的话，也不要把多个实体用户共用同一设备等同于同一身份。

目前没有随仓库交付 ESP32 固件、ASR/TTS 管线、MQTT 适配器或硬件控制工具。这里描述的是可复用核心能力的应用方向；接入实现及验证完成后再列为正式支持。

## 6. 发布验收

接入端至少核对：合法/非法账号连接、会话隔离、原消息去重、正常收发、失败及断线回执、重连后身份稳定、私聊授权。启用图片、文件、引用、媒体或设备动作时，再逐项验证对应扩展。模型费用、第三方服务及设备运行条件应在各接入端文档单独说明。
